# Model registry

The model registry is a catalogue of the models your project uses. Register a model once, with its capabilities and default parameters, then choose it for a prompt version. The model and any parameter overrides are versioned with the prompt and carry into the [playground](/docs/prompt-management/features/playground), [experiments](/docs/evaluation/experiments/experiments-via-ui), and the API. You can also start an experiment or choose an evaluator's judge model straight from the registry.

Typical uses:

- Pin a prompt to the model it was written for, so everyone who opens it in the playground starts on that model.
- Record which models support tool calling or vision, and mark older models as deprecated so nobody picks them for new prompts.
- Read a prompt's model and default parameters in your application instead of hardcoding them.
- Run an experiment on a registered model, see which experiments each model has run, and get a warning when a dataset doesn't fit the model.
- Choose the judge model for [LLM-as-a-judge](/docs/evaluation/evaluation-methods/llm-as-a-judge) evaluators from the same list.

<Callout type="info">
The registry says **which models you use**. [Model definitions](/docs/observability/features/token-and-cost-tracking) hold the prices Langfuse uses to calculate cost, and the prompt [`config`](/docs/prompt-management/features/config) holds anything else you want to attach to a prompt, such as tool definitions or a response schema. They work side by side and none replaces another.
</Callout>

## Register models [#register-models]

Open [Models](https://cloud.langfuse.com/project/~/models) in the sidebar, under **Context management**, and click **Add model**.

| Field                                | What it holds                                                                                                                                                              |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Provider                             | The name of the [LLM connection](/docs/administration/llm-connection) that runs the model. Together with the model ID it must be unique in the project.                    |
| Model ID                             | The model name as your provider expects it.                                                                                                                                |
| Display name and description         | How the model appears in Langfuse.                                                                                                                                         |
| Status                               | `active` or `deprecated`. Deprecated models stay in the registry but are hidden when you choose a model for a prompt.                                                      |
| Context window and max output tokens | The model's limits, in tokens.                                                                                                                                             |
| Capabilities                         | Whether the model supports tool calling, vision, JSON mode, and reasoning.                                                                                                 |
| Default parameters                   | The temperature, top P, max tokens, reasoning budget, and provider options that prompts start from. See [reasoning and provider options](#reasoning-and-provider-options). |
| Pricing                              | The model definition that prices this model. See [token and cost tracking](/docs/observability/features/token-and-cost-tracking).                                          |

Only the provider, model ID, and display name are required.

<Frame>
  ![The Edit model dialog showing display name, provider, model ID, status, context window, output limit, and capability switches](/images/docs/model-registry-edit-dialog.png)
</Frame>

The **Connection** column shows whether an LLM connection with the provider's name can run the model.

### Import from connections [#import-from-connections]

Click **Import from connections** to register every model your LLM connections offer. Models that are already in the registry are left as they are, so you can run it again after you add a connection.

<Callout type="info">
Project owners and admins can add, edit, and delete models. Everyone who can read prompts can choose from the registry. You can't delete a model while prompt versions still use it. Langfuse shows how many do.
</Callout>

## Reasoning and provider options [#reasoning-and-provider-options]

Some models take settings beyond temperature, top P, and max tokens, such as how much a reasoning model thinks. A registry model can hold two of them as defaults:

- **Default max reasoning tokens** is the token budget for model thinking. Use `-1` to let the provider decide and `0` to turn it off. Langfuse applies it to Gemini models on Vertex AI, where it takes precedence over `thinkingBudget`. For other providers, set the budget through provider options.
- **Provider options** is a JSON object of extra options that Langfuse sends to the provider. Langfuse translates them for the provider that runs the model.

| Provider                                | Option                                                                          | Example                                                      |
| --------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| OpenAI and Azure OpenAI                 | `reasoning_effort`                                                              | `{"reasoning_effort": "high"}`                               |
| Anthropic                               | `thinking`                                                                      | `{"thinking": {"type": "enabled", "budget_tokens": 2048}}`   |
| Google AI Studio and Vertex AI (Gemini) | `thinkingBudget` for Gemini 2.5 models, `thinkingLevel` for other Gemini models | `{"thinkingBudget": 1024}`                                   |
| Amazon Bedrock                          | Options in the AI SDK shape, such as `reasoningConfig`                          | See the Amazon Bedrock documentation for the supported shape |

Check your provider's API reference for the values it supports. An option that Langfuse does not recognise for the provider is rejected with an error when the model runs. The exception is a custom OpenAI-compatible endpoint, which receives unknown options as written.

These settings are part of the model's parameters. A prompt that uses the model gets them in its [effective `model.params`](#read-the-model), and the [playground](/docs/prompt-management/features/playground) starts with them switched on when you open the prompt. A prompt version can still override them in `modelParams` through the API, and its values win over the registry's for the keys it sets.

## Choose a model for a prompt [#choose-a-model]

When you create a prompt version, pick a model in the **Model** field above the config. You can override the temperature, top P, and max tokens for this version. A field you leave empty uses the model's default, which the field shows as a placeholder.

A new version starts from the model and overrides of the version you build on. The prompt's **Config** tab shows the model and any overrides.

<Frame fullWidth>
  ![The new prompt version form with a Model selector and Temperature, Top P, and Max tokens fields that show the model's defaults as placeholders](/images/docs/model-registry-prompt-model.png)
</Frame>

To set it from the API, pass `registryModelId` and `modelParams` when you create the prompt. The ID comes from `GET /api/public/registry-models`.

```bash
curl -X POST "https://cloud.langfuse.com/api/public/v2/prompts" \
  -u "$LANGFUSE_PUBLIC_KEY:$LANGFUSE_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "support-assistant",
    "type": "text",
    "prompt": "You are a helpful support assistant for {{product}}.",
    "registryModelId": "<registry-model-id>",
    "modelParams": { "temperature": 0.3 }
  }'
```

## Use the model in the playground and experiments [#playground-and-experiments]

- **Test in LLM playground** on a prompt opens the [playground](/docs/prompt-management/features/playground) with the prompt's model and parameters set, as long as one of your LLM connections can run the model.
- **Save as prompt** in the playground starts the new prompt with the playground's model and the parameters you switched on, if that model is in your registry.
- **Run experiment** on a prompt selects its model and parameters in the [experiment](/docs/evaluation/experiments/experiments-via-ui) setup. See [run an experiment on a registry model](#run-experiments).

## Run an experiment on a registry model [#run-experiments]

In the [experiment](/docs/evaluation/experiments/experiments-via-ui) setup, the **Registry model** field above the provider and model fields lists the active models in your registry. Type to search it.

- Choosing a model fills the provider, the model, and the model's default parameters. You can still change any of them.
- A model whose provider has no matching [LLM connection](/docs/administration/llm-connection) is marked **no connection**. Add the connection before you run it.
- If the prompt has a model, the field starts on it. Choose **Other model** to pick the provider and model yourself, as before. Editing the provider or model fields after you choose a registry model also switches the field back to **Other model**, because the run no longer uses that registry model.

The run records which registry model it started from. The experiment's details panel shows the model's display name with its provider and model ID, and links to it on the Models page. Experiments that were started before this existed, or from **Other model**, still show the registry model when their provider and model match one in the registry.

### Warnings before you run [#capability-warnings]

Once you choose a dataset, the setup checks the registry model against the dataset and the prompt and shows a warning for each mismatch. It shows them again on the review step. A warning never stops you from running the experiment.

| Warning        | When it appears                                                                                                                                                  |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Vision         | Dataset items contain images or media, and the model is not marked as supporting vision.                                                                         |
| Tool calling   | The prompt defines tools, and the model is not marked as supporting tool calling.                                                                                |
| JSON mode      | Structured output is on, and the model is not marked as supporting JSON mode.                                                                                    |
| Context window | The longest dataset item is longer than the model's context window. Langfuse estimates the length as one token per four characters, so the count is approximate. |

<Callout type="info">
Capabilities start switched off in the registry, so "not marked as supporting" can also mean nobody filled it in. Set a model's capabilities and context window in its [registry entry](#register-models). A model with no context window gets no length warning, and a model you pick with **Other model** gets no warnings, because Langfuse has no registered capabilities to check.
</Callout>

## Use a registry model for evaluators [#evaluators]

The same **Registry model** field is on the forms where you choose the model that scores your data with [LLM-as-a-judge](/docs/evaluation/evaluation-methods/llm-as-a-judge):

- the [project default model](/docs/evaluation/evaluation-methods/llm-as-a-judge#project-default-model), and
- the custom model of an evaluator, which you see after you turn off **Use default evaluation model**.

Choosing a model fills the provider, the model, and the model's default parameters, and you can still change them. The evaluator stores the provider, model, and parameters, not a link to the registry entry. When you open the form again, the field shows the registry model whose provider and model the fields hold, or **Other model** if there is none.

Evaluators read structured output from the judge, so a model that is not marked as supporting JSON mode shows **not marked for JSON mode** in the list. Langfuse doesn't hide it, because the capability may simply be unset.

## See how a model is used in traces [#model-in-traces]

Langfuse matches the model name on each generation to a [model definition](/docs/observability/features/token-and-cost-tracking) to calculate its cost. A registry model that is linked to a model definition through its **Pricing** field is connected to every generation that matched that definition.

- **Usage on the Models page.** The **Last used** column shows when a generation last used the model. **Generations, 30d** counts the generations from the last 30 days. A model without a pricing link shows **Link pricing** instead, because Langfuse has no way to tell which generations used it.
- **Experiments on the Models page.** **Experiments, 30d** counts the experiments from the last 30 days that ran on the model, and **Datasets, 30d** counts the datasets they ran on. An experiment counts for the registry model it started from, or, when it didn't start from one, for the provider and model it ran on. These columns need [Langfuse v4](/docs/v4), the same as the Experiments page. Without it they show a dash.
- **View experiments.** Open the row menu of a model and click **View experiments** to open the Experiments page filtered to the runs on that model's provider and model.
- **View generations.** Open the row menu of a model and click **View generations** to open the generations table filtered to that model, for the last 30 days. The action is disabled until the model has a pricing link.
- **The model on a generation.** In a trace, the model name in the header of a generation links to the matching registry model on the Models page.
- **Prompt model mismatch.** When a generation uses a prompt version that has a model, and the generation ran on a different model, the header shows a **prompt expects** link to the model the prompt names. Langfuse compares the linked model definitions, not the names, so a dated model name such as `gpt-4o-2024-08-06` is not flagged when it matches the same definition as the prompt's model. Nothing is flagged if either model has no pricing link.

<Callout type="info">
Two registry models that link to the same model definition share the same usage numbers.
</Callout>

## Read the model in your application [#read-the-model]

A prompt that you fetch through the API includes its model:

```json
{
  "name": "support-assistant",
  "registryModelId": "<registry-model-id>",
  "modelParams": { "temperature": 0.3 },
  "model": {
    "provider": "my-connection",
    "modelId": "my-model-id",
    "params": { "temperature": 0.3, "max_tokens": 1024 }
  }
}
```

- `model` is resolved from the registry. Its `params` are the model's default parameters with the prompt's `modelParams` applied on top. It is `null` for a prompt without a model.
- `GET /api/public/v2/prompts` returns `lastModel` for each prompt, in the same shape.
- The MCP prompt tools accept and return the model. See the [MCP server](/docs/api-and-data-platform/features/mcp-server) docs.
- The `/api/public/registry-models` endpoints let you list, create, get, replace, and delete models. See the [API reference](https://api.reference.langfuse.com/#tag/registrymodels).

<Callout type="warning">
SDKs cache prompts client-side, so a change to a registry model can take up to the cache TTL to reach your application. See [caching](/docs/prompt-management/features/caching).
</Callout>
